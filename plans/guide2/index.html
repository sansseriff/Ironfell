    Four foundations, nine parts, and a field guide

    Iron, Part Two

    How Iron works as of commit 480c15b. Four Foundations pages explain the core that everything rests on: a document store with ids, typed values, ops, undo, bindings and clips, the bridge that draws it in Bevy, and the model surface that lets Claude edit it. Nine Parts then cover what was built on top of it between October 10 and 12: units and definitions, drags that run through the store, a constraint solver, compositions that nest inside each other, a renderer where every view is a texture, Figma's select tool and a pen, a dock of tabs and a session tier, and ports that wire a laser to a fiber to a meter.

    Written forYou, reading offline. You know the project and its vision documents. Rust is the part you're less sure of, so Foundations 1 ends with a phrasebook.
    How to read itIn order. Foundations 1–4 first (they replace the older plans/guide/, which you can skip). Then Part 1 is the map; Parts 2–4 are the store; 5–8 are what you see and touch; Part 9 wires entities together.
    What it covers52 commits, 5ee0b93 to 480c15b on branch document-spine: roadmap stages A, B, C1, C2, D, E and F steps 1–3, plus embeds, view textures, the dock and the session.

    Reading it offline

    Everything these pages need is in this folder: the stylesheet, the script and the syntax highlighter (highlight.min.js) are local files. Open plans/guide2/index.html in a browser and read. Without a network connection the text falls back from its web fonts to system ones, and nothing else changes. The vscode:// links only work on a machine with this repository and VS Code.

    The sources are in _src/. If the code changes, python3 plans/guide2/_src/build.py regenerates every page, and fails if a reference no longer points at the line it describes.
