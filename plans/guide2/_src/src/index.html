Four foundations, fourteen parts, and a field guide

Iron, Part Two

How Iron works in the checkout at 5334ab8, reviewed October 28, 2026. Four Foundations pages explain ids, facets, ops, undo, bindings, clips and the bridge. Fourteen Parts follow the system from values and linked components through constraints, compositions, cached rendering, tools, text and tables, the workspace, port networks and electrical schematics, shared host protocols, producers, gestures and contexts. Examples and excerpts describe the current implementation; historical measurements are labelled separately.

Written forYou, reading offline. You know the project and its vision documents. Rust is the part you're less sure of, so Foundations 1 ends with a phrasebook.
How to read itIn order. Foundations 1–4 first (they replace the older plans/archive/guide-spine/, which you can skip). Then Part 1 is the map; Parts 2–4 are the store; 5–8 are what you see and touch; Part 9 wires entities together; Parts 10–13 are the engine boundary; Part 14 is behaviour as data, and opens with a one-page map of the app as it stands. If you read the October 17 edition, revisit Parts 2, 6, 7, 9 and 11–12, then Part 14.
What it coversThe history from the original October 13 guide (b6e21bf, Foundations 91a4454) through 5334ab8. The source README records the audit by subsystem. The roadmap and handoffs remain authoritative for what to do next.

Reading it offline

Everything these pages need is in this folder: the stylesheet, the script and the syntax highlighter (highlight.min.js) are local files. Open plans/guide2/index.html in a browser and read. Without a network connection the text falls back from its web fonts to system ones, and nothing else changes. The vscode:// links only work on a machine with this repository and VS Code.

The sources are in _src/. If the code changes, python3 plans/guide2/_src/build.py regenerates every page, and fails if a reference no longer points at the line it describes.
