    One frame, in order

    One engine runs in three places: a browser worker, browser main-thread wasm, or a native macOS host. They share input and document semantics, but acquire input, own surfaces and schedule frames differently. This part follows a request into the engine, through the two document syncs, into rendering and back to the shell, then separates engine completion from display presentation.

    You needF4 (bridge), Part 6 (caches), Part 10 (spatial scene and entities).
    Filessrc/{engine_protocol,engine_dispatch,engine_api,host_events,web_ffi,lib}.rs, bevy_app/mod.rs, document_bridge/{mod,ui}.rs; src-ui/runtime/; src-native/src/.

    11.1Three runtimes, one protocol

    RuntimeHost workShared engine work
    Browser workerOffscreenCanvas, rAF; sample latest pointer motion at a worker frameengine_protocol::Request dispatches ordinary input/control and document messages. engine_dispatch::call validates named document commands and calls engine_api.
    Browser main threadHTMLCanvasElement, rAF; pointer motion enters wasm immediately
    Native macOSTauri window, Metal surface, transparent WKWebView shell; AppKit pointer monitor, bounded mailbox and native pacing

    BrowserRuntime owns both browser modes' bootstrap, resizing, frame loop, disposal and font loading. Worker/main adapters no longer duplicate that lifecycle. Native retains its own surface and clock. The native pointer uses the latest AppKit sample, bypassing webview motion IPC; buttons, keys, wheel and document calls still use the shared request protocol.

    Rust defines the request/event union. bun run protocol:generate generates TypeScript wire types and named document commands; bun run check checks freshness and negative type fixtures. The low-level document call still carries a name and JSON arguments, checked for unknown names, arity and types before touching the world.

    The TypeScript model API is built by makeDocumentApi(call) over synchronous or asynchronous transports. The model parser therefore works on native as well as wasm; its code must await calls rather than assume the store lives beside it.

    11.2When a request takes effect

    RouteExamplesMeaning
    Read nowsave, view, inspect, schema, signals, allocation queriesRead the current engine state.
    Apply nowmodel apply, inspector field edit, freeze, LinkApply a store transaction between frames; the sync later finds it in the log.
    Queuetool keys, pointer edges, paste, validated loadRecord work for the next system pass. SVG import prepares a paste rather than installing its nodes directly.

    A model edit includes expect_version. A changed authored version rejects the stale edit before apply. A valid edit arriving during a gesture is classified against that gesture, applied without its previews, then resumes or cancels it (Part 13). Request acknowledgments distinguish queued, applied and completed work; none certifies that pixels reached the display.

    11.3The current frame

    The important ordering is explicit in bevy_app/mod.rs and document_bridge/mod.rs. Systems outside these chains can run independently subject to their declared resource access and before/after constraints.

    PhaseWork and ordering
    Before frameHost samples motion and dispatches requests. Native processes a bounded batch and stops at button/key edges; a release with fresh motion can wait a tick so the final preview is seen.
    PreUpdategas::step_and_publish → stats::step_and_publish → motion::advance → text::refresh_text → sync_document → decide_modes → sync_live → resolve_panel_views. Picking follows the sync and pointer-panel routing.
    UpdateCamera/panel management, focus requests, mesh material assignments and other host-facing work.
    PostUpdate: interactionRoute view keys; navigate and run select, pen, shape, text, port, table and wire tools. Sync selection and publish interaction state. Resolve each view's focus after the select tool.
    PostUpdate: document barriersync_document → ApplyDeferred → resolve_panel_views after all editing tools and selection/state publication, before transform propagation. This applies commits, structural edits and history and drains previews in their input frame.
    PostUpdate: presentationPropagate Bevy-owned transforms; update the spatial scene; collect embed views and compute liveness before view cameras; record changed document chunks and draw overlays. Dependencies order cameras, planes, layers and inspectors where required.
    LastReport work queued too late, coalesce UI changes, decide whether rendering is needed.
    After main worldRun extraction/rendering if needed, then drain engine events through the host transport.

    The same sync_document runs twice. There is no separate reconcile_gesture system now. The second sync is what makes a pen click, shape creation, delete, undo or gesture release visible without waiting for another frame. A preview-only sync is still measured under the GestureReconcile timing phase.

    Inside each sync

    1. Return if queues, resolved changes and authored version are all unchanged.
    2. Install a validated pending document, clear old draw data/entities and renew document identity.
    3. Apply pending transactions, then gesture commits/cancels, then undo/redo requests.
    4. Read log entries since the synced version: collect affected ids from authored ops, solver-derived ops, inverses and expansion ops. Expansion is visible to consumers without becoming authored history.
    5. Ensure the session Library and Stats compositions exist. Drain moved resolved values, including producer outputs and gesture previews.
    6. Record UI invalidation and geometry changes, reconcile affected draw data/entities and refresh paint order when structure changed.

    Undo and redo enter through ToolKeys, alongside Delete, so a delete followed by undo can reach the post-tool sync together. Queue classes still have fixed ordering: arbitrary interleaving of transaction-producing keys and undo inside one frame is not a general ordered command log.

    11.4A drag and a model edit

    A model edit between frames applies immediately after the version check. If it conflicts with the active gesture, the store cancels that gesture; the tool notices its token is cancelled and its later release writes nothing. Compatible edits preserve the previews. Both edits reach the bridge through the transaction log, irrespective of which host delivered them.

    11.5Events, reads and session lifetime

    HostEvents is a thread-safe outbox. Browser modes serialize the Rust event union through one rustBridge.send_event_from_worker callback; native sends the same event union over its channel. Fonts remain a host service. ui::publish coalesces authored, session and resolved revisions, affected nodes, composition/structure flags and explicit undo/redo availability once per frame.

    The shell's QuerySubscriptions shares cached reads by command. An inspector subscribes to its node; composition lists subscribe to composition changes; whole-document views use one authored-content interest. Hidden/unmounted consumers release interests. Unobserved Stats changes therefore do not wake unrelated shell reads.

    PendingRequests tracks session identity, timeouts and disposal. Replacing or failing a runtime settles pending requests and rejects stale events/results. Generation checks stop a delayed response from a previous runtime replacing the current inspector. Native webview reload can reattach to the existing engine and history; a browser runtime replacement carries canonical document content into a new engine.

    11.6Engine frames and displayed frames

    WorkerApp::frame updates the main world, then runs the render sub-app only when redraw is needed. Free-running compositions, motion and pending raster work keep it active; static hidden views do not. Stats is live until set to On demand. Completion of this function, CPU present return, GPU completion and actual presentation are separate milestones.

    The native host offers stock pipelined/display, older sync/late, and newer late-fifo and adaptive presets. Late-fifo uses a CVDisplayLink vsync grid, drawable presentation feedback to drain backlog, and a GPU-aware budget to start near the next compositor pickup. Adaptive engages this scheduling while a left button or document gesture is active and returns to stock scheduling otherwise. Browser rAF exposes none of those native controls.

    The October 27 native investigation measured roughly 21–24 ms Metal presentation delay during paced drags on its tested 60 Hz displays, compared with roughly 45 ms stock pacing. This excludes input delivery and work before present; it is not an input-to-photon result. Just-in-time pacing exposes occasional repeated frames that the stock queue absorbs. Physical input-to-photon, 120 Hz and other environments remain unmeasured. The native pacing synthesis owns the conditions, trade-offs and open questions; src-native/README.md owns the launch controls.

    Before you go on
    • Hosts own acquisition, surfaces and clocks. Rust owns shared request/event semantics and document dispatch.
    • Producers publish before the first sync; tools edit before the second. Reconciliation follows logs and resolved changes.
    • The shell subscribes to scoped reads with session lifetime protection. Engine acknowledgment does not promise display presentation.
