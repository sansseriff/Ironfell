    Richer values and definitions

    The first guide's document stored numbers, strings, colours and vectors, and every node type was a Rust enum variant. Then the optics demo appeared on the horizon. A laser has a power in milliwatts, a fiber has a loss in dB per km, and a "laser" is not something the Rust code should know about. This part covers roadmap stage B: quantities with units, structured records, fields whose names are only known at run time, and definitions that live in the document as data.

    You needFoundations 1 and 3: facets, slots, Value, and the expression language.
    Filesiron_document/src/{units,value,sym,facet,definition,expand,serial}.rs, expr.rs's arithmetic, and the demo's bar in document_bridge/demo.rs.

    2.1Quantities: a number that knows its unit

    The simple version

    Store numbers and write the unit in the name. A field called power_mw holds 9.58. It works until someone binds power_mw to a field called power_w, and the laser is a thousand times too bright with no error anywhere. Unit mistakes are silent by construction.

    What was built

    A quantity is an SI magnitude plus a dimension. 9.58 mW is stored as {si: 0.00958, dim: W}. The unit someone typed is presentation only. Arithmetic checks dimensions, so adding watts to kelvin is an error you see the moment you write the binding.

    A dimension is seven small integers: the exponents of metre, kilogram, second, ampere, kelvin, mole and candela. Watts are kg·m²·s⁻³, so their Dim is [2, 1, -3, 0, 0, 0, 0].

    Multiplying two quantities adds their exponents, dividing subtracts them. A result whose exponents are all zero is a plain number again, which is why signal / 1 mW gives a dimensionless ratio you can use as a width in pixels.

    Units come in as text, in files, in expressions, and from the model. parse_unit reads any prefixed or compound unit:

    It splits on the one /, multiplies the atoms on each side, and each atom may carry a prefix (mW, µs) and a power (m2, s^-1). The result is a Unit: a dimension and the factor that turns a magnitude in this unit into SI. So K/W parses to dimension K·kg⁻¹·m⁻²·s³ with factor 1, which matters later: the thermal link's resistance is written 2 K/W in Part 9.

    Going the other way, format picks an engineering prefix so the mantissa reads between 1 and 1000:

    That's what you see in views and in the inspector: 7.94 mW, not 0.00794 W.

    The value enum, now

    Two variants are new since the first guide. Quantity is above. Record is a small structured value with a named schema (a beam with a waist and a wavelength, say). Its fields are read in expressions with dot syntax, #e.args.beam.waist, which parses to Expr::Get. Records exist for the time-domain work in Part 9's future; nothing in the demo uses one yet.

    In files, a quantity is written as {"q": [si, "canonical unit"]}, always in the coherent SI unit, so diffs stay readable. The model surface may also send {"q": "9.58 mW"}, because the model doesn't carry the unit table:

    Arithmetic that checks dimensions

    Addition, subtraction, remainder and comparison need equal dimensions; multiplication and division combine them. A plain number is a quantity with no dimension, so 9.58 mW * 2 is fine and 9.58 mW + 2 is the error cannot combine 9.58 mW + 2. That's exactly the warning you'd have seen in the thermal demo before its port defaults were fixed: cannot combine a plain number - K.

    The lexer turns a number followed by unit characters into a quantity literal, so 640 - x * 300 stays plain numbers while x / 1 mW reads 1 mW as one token (expr.rs:689). The same stage added the floor functions geometry needs (sin, cos, atan2, sqrt, pow, hypot) and the constant pi. The fiber's loss in Part 9 is pow(10, -loss * length / 10).

    Reading the Rust

    fn quantity_op(...) -> Option<Result<Value, EvalError>> has two layers of "maybe". The outer Option says "is this my case at all?": a.as_quantity()? returns None early if either side isn't a number or quantity, and binary then tries vectors and strings. The inner Result says "it is my case; did it work?". same().map(|_| ...) runs the closure only when the dimensions matched.

    2.2Fields named at run time

    The fixed bundles of leaves are facets: size.w, fill.color, transform2d.x. The store renamed its old Component enum to Facet on October 18, leaving “component” for a reusable authored thing. An entity's arguments have names declared by its definition, so args is a dynamic facet. Names are interned once into shared &'static strs; LeafPath stays cheap to copy.

    For example, a bar entity's args.level can bind to #slider.slider.value. The input port's signal reads that argument unless a connection feeds it. The same graph, handle inversion, validation and undo work for these leaves as for a rect's width.

    2.3Definitions expose ports

    The old representation

    A definition declared parameters separately from its ports, and placing it copied every picture into authored nodes. Edits to the definition could not update those copies.

    The current model

    A definition declares in ports with defaults, output ports with behaviour bindings, pair terminals and equations, and a template per notation. An entity supplies arguments; each use draws that entity in a notation. Linked instances derive their ports and pictures from the definition.

    inputs_of reads the input specs; validate_entity requires exactly their names and checks constant kinds and quantity dimensions. Templates read port.signal, so the library can display a definition at its defaults before any instance exists.

    Placing an instance creates an entity and a use

    instantiate allocates two authored nodes and a figures relation. It returns ops for a transaction; it does not mutate the document. No template subtree is authored at placement time:

    place_figures adds another use for an existing entity. Its arguments and ports stay shared, while each use chooses a notation and placement. instantiate_static is the explicit copying alternative; detach_ops turns a linked instance into authored copies. Old files migrate to detached mode so loading preserves their previous meaning.

    2.4Authored state and expanded state

    expand.rs derives the ports, equations and picture children beside the authored nodes, through the op applier. Expanded identities are paths such as #m/7, built from the owner and the definition-local id; nested instances extend that path. Re-expansion, undo and reload retain those identities. The canonical file excludes expanded nodes and relations, then derives them again on load.

    Edits inside a linked picture are translated into authored override records. Editing a definition changes all linked instances, except where an instance overrides that leaf. The authored input is therefore the definition, the entity's arguments, the use and its overrides; the expanded nodes are the current evaluated picture. A main is a use that edits the definition itself. Scope controls whether an edit reaches a component or one of its parts.

    Store::make_component builds a definition from selected instances, including nested components, returning one transaction. The port, empty and joint tools expose its interface on the canvas; the session's Library composition offers standard components. Rendering also has lightweight references: a use naming a definition directly, with no figured entity, can draw a repeated SVG template without expanding a node tree (Part 6).

    2.5The file now uses schema 8

    Schema 3 renamed depiction/depicts to template/figures; 4 made circles ellipses; 5 introduced contours; 6 replaced parameter specs with input ports, params with args, and the components table with facets; 7 made linked instances explicit; 8 added packed path geometry. The loader accepts schemas 1–8 and migrates the old representations. New saves contain authored facets, never expanded pictures, session state or runtime signals.

    serial::SCHEMA
    Current limits

    Expansion still computes the whole wanted set before reconciling it. Cross-document libraries await the project container; detaching nested instances and richer override UI remain follow-ups in plans/specs/component-model.md. Definitions are not an excuse to put derived state in the file.
