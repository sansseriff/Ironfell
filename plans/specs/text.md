# Text

**Status:** scaffold done 2026-10-17; colour emoji, styled parts (runs),
underline and strikethrough, pasting plain text, and SVG `<text>` export added the
same day. Text nodes, a font catalog loaded on
demand, glyph outlines through the ordinary fill path, a Figma-style text tool and
editor, a Text inspector section with a font picker, `fmt`/`sci`/`str`, and
installed fonts on the native host. Open items are listed in §9.

This spec came out of a conversation on 2026-10-17 about how Figma puts text on its
canvas, what `vello_gpu` offers for text, how fonts are loaded, and how text must
serve live readouts, graphs and displays.

## 1. Decisions

| Question | Decision | Why |
|---|---|---|
| Where layout lives | A Bevy-free crate, `src/iron_text`, used by the store (bounds, picking) and the renderer | Bounds and glyphs must agree, and `iron_document` must stay free of renderer types |
| Shaping stack | parley 0.11 + skrifa 0.44 | Bevy 0.20's `bevy_text` already links exactly these, so the app carries one font stack |
| Drawing glyphs | Outlines from skrifa, cached per glyph, emitted as a `Fill` of one path per text | Fill, stroke, gradient, shadow and opacity work on text with no text-specific backend code; `vello_gpu`'s `glyph_run` needs the renderer's `Resources` at encode time, which `hybrid.rs` does not have (§5) |
| Fonts on the web | A curated catalog of variable TTFs, self-hosted in `public/fonts/`, fetched by the host when a document or the picker needs one | Startup fetches nothing it would wait on; a variable file serves every weight |
| The picker's previews | One `previews.json` of SVG paths, generated by `iron_text`'s `font_previews` bin | Shows every family in its own face without fetching any font file. The paths come from the same layout and outline code the canvas uses |
| Live text | `text.content` is an ordinary leaf. Formatting is an expression (`fmt`), not a node feature | Bindings, signals and ports already reach any leaf; the formatting stays visible and undoable |
| Editing | Figma's hidden-textarea technique; the engine draws the caret and selection | IME, dead keys, clipboard and word motion stay the platform's |
| `bevy_text` | Unused by the canvas; kept for the FPS overlay | 3D text, when it comes, is a 2D view's texture on a plane, not meshes (§9) |

## 2. The text node

Type `text`. Components: `transform2d`, `text`, `font` (required); `size`, `fill`,
`gradient`, `appearance`, `stroke`, `shadow`, `name`, `host` (optional). Its origin is
the box's top-left, as a rect's is.

- `text.content` (Str): the words.
- `text.sizing` (Enum): `auto_width` (no wrapping; the box fits the text),
  `auto_height` (wraps at `size.w`; the height fits), `fixed` (`size.w` × `size.h`;
  text may overflow). A click with the tool makes `auto_width` text, and a drag
  makes `fixed` text, as in Figma.
- `font.family` (Str, default `Inter`), `size` (24), `weight` (400), `italic`,
  `line_height` (a percent of size; 0 means Auto, the font's metrics),
  `letter_spacing` (a percent of size), `align` (`left`/`center`/`right`),
  `valign` (`top`/`middle`/`bottom`; only a fixed box has room to use it),
  `tabular` (tabular figures, so digits stay put).

`font.underline` and `font.strike` decorate the whole node.

### 2.1 Styled parts

`text.runs` (Str) holds JSON: byte ranges of `content`, each with the properties it
overrides, for example `[{"start":0,"end":5,"weight":700},{"start":6,"end":10,"color":[1,0,0,1],"underline":true}]`.
The overridable properties are `family`, `size`, `weight`, `italic`, `color`,
`underline` and `strike`. `iron_text::runs` keeps the list normal: sorted,
disjoint, on character boundaries, with equal neighbours merged.

- **Editing:** each edit carries the runs across (`runs::remap`). Typed characters
  take the style of the character before them; deleted ones take theirs away.
- **Styling while editing:** with characters selected, the inspector's family,
  weight, size, colour and the B/I/U/S toggles style that range, as do ⌘B, ⌘I, ⌘U
  and ⌘⇧X. The range is previewed with the edit and committed with it as one
  transaction.
- **Styling the node:** with no range selected, a change goes to the whole node
  (`text_style`), and every run loses the property it set, as in Figma.

One leaf keeps an edit to the words and their styling to one `Set` each. It also
means a styled part cannot be bound on its own: bind the whole content, or use
two nodes.

## 3. Measuring

`iron_document::text::measure(store, id)` resolves the style and content, lays out
through `iron_text::engine()`, and returns the layout, the box (`frame`), and the
vertical-alignment offset. `geom::local_bounds` uses the box. `effect_of`
classifies `text` and `font` changes as local geometry, so the spatial scene
re-indexes text when its words change.

Layouts are cached by (text, style, wrap width) and shared through `Arc`, so a
readout reshapes only when its string changes.

## 4. Fonts

### 4.1 Fonts are a process resource

There is one `TextEngine` per process (`iron_text::engine()`), like a native app's
system font list: loading a document replaces the store, not the fonts. Registering
font bytes (`TextEngine::register`) moves the engine's generation;
`Store::refresh_text`, called each frame by `document_bridge::text::refresh_text`,
reports every text node as changed when the generation moved, so text re-measures
and redraws.

A layout that asks for a family the engine lacks:

- lays out in `DEFAULT_FAMILY` (Inter), or as a size estimate before any font has
  arrived, and is marked `pending`;
- notes the family as *wanted*. The engine asks the host for wanted families once
  per frame (`EngineEvent::Fonts`), most needed first.

A family in no catalog, and not installed, is `missing`. It draws in the default
face and the inspector says so, as Figma does. The document keeps the name.

### 4.2 The web host

`src-ui/runtime/font_loader.ts`, in the worker (or the main-thread adapter):

- fetches `${BASE_URL}fonts/<file>`, at most two at a time;
- puts new requests at the front of the queue;
- caches files in the Cache API (`iron-fonts-v1`), so a second visit reads them
  from disk;
- passes the bytes to `register_font`.

At startup the engine asks only for the default face, after the app runs. Nothing
waits on it.

The catalog is `iron_text::catalog::FAMILIES`: 15 variable families, 6.1 MB in all
(upright only), under the SIL Open Font License (`public/fonts/OFL.txt`). To add a
family, put the TTF in `public/fonts/`, add a row, and rerun:

```sh
cargo run -p iron_text --bin font_previews --target aarch64-apple-darwin
```

skrifa does not read WOFF2, so catalog files must be TTF or OTF.

### 4.3 The native host

The native build enables `iron_text/system`. fontique then enumerates installed
fonts (CoreText on macOS, DirectWrite on Windows, fontconfig on Linux) and loads a
file only when a layout uses it. Installed families appear in the picker under
*Installed*. Their previews come from the engine (`font_previews`) a page at a time
as the list scrolls. Catalog files are read from the bundled frontend through
Tauri's asset resolver instead of being fetched.

Figma desktop, and Figma in a browser with its font helper, do the same thing; the
browser alone cannot list installed fonts. A document that uses an installed font,
opened on the web, shows that font as missing.

## 5. Rendering

`materialize` gives a text node `Shape2d::Text { w, h, glyphs, layout, offset }`:

- its box is the shape that picking, hover and selection use;
- its glyph outline, one path, is what `render.rs` fills, strokes and shadows.

Glyph outlines are unhinted, in font units, and cached per (font, glyph, variation
coordinates) in `iron_text::outline`. Synthetic italic applies the run's skew.

A layout's `paints` are, in order:
- one fill of outline glyphs plus underlines and strikethroughs for each colour
  (the node's own paint, then each run colour);
- one `TextPaint::Color` per colour glyph.

### 5.1 Colour glyphs and emoji

`iron_text::color` records a COLR glyph's paint graph (v0 layers and v1 gradients,
via skrifa's `ColorPainter`) as `ColorOp`s in font units: clip to an outline, fill
with a solid colour or a peniko gradient, layer. They are cached per glyph.
`render.rs` replays them as `PushClip`/`Fill`/`PopLayer` display-list commands.
Composite modes other than source-over draw as source-over. The text-colour
palette entry takes the run's or the node's colour.

Composite modes are honoured: a COLR layer becomes a `DrawCmd::PushBlend` group
(`vello_gpu`'s `push_blend_layer`). Noto's flags need this to mask and multiply
their sheen. A glyph whose layers are all source-over has them dropped at record
time, since each layer costs an offscreen pass.

Emoji are part of their text node's layout and draw data, like any other glyph.
They are never document nodes or entities. Repeated emoji share one cached list of
ops.

**The emoji font.** Noto Color Emoji, COLR v1 (`Noto-COLRv1.ttf` from
googlefonts/noto-emoji, 5 MB, SIL OFL; `public/fonts/emoji/LICENSE`), split by
`src/iron_text/tools/split_emoji.py` into chunks that load on demand:

- **10 single chunks** of 126–366 KB, in codepoint order. They hold single emoji
  only.
- **8 sequence chunks.** These hold everything that joins emoji: skin tones, ZWJ
  families and gendered people, flags, and tag flags.
- **Why sequences are separate.** Sequences are most of the font's weight, so a
  plain smiley costs one small chunk. Single chunks leave out ZWJ, the tone
  modifiers, tags and regional indicators, so the subsetter can't pull a
  sequence's ligature into them.
- **Why the sequence chunks stay large.** Person sequences share body and hand
  outlines across emoji. Splitting them finer duplicates those drawings into
  every piece: 18 MB in all, against 5.9 MB as built. The largest sequence chunk
  is about 2 MB.

Each chunk is its own family (`Noto Color Emoji 01`, `… Seq 01`), because parley
picks one font per family. `chunks.json` maps each chunk's home codepoints, and
`iron_text::catalog::emoji::needed` asks for:
- an emoji's single chunk;
- its sequence chunk too, when something joins it (a ZWJ, a tone or a tag, past
  any variation selector) or it starts a flag.

Every family's fallback list is the family, then Inter, then every emoji chunk,
sequence chunks first, so a loaded sequence chunk shapes the whole sequence. To
rebuild after a new Noto release:

```sh
uv run --with fonttools python -I src/iron_text/tools/split_emoji.py \
    path/to/Noto-COLRv1.ttf public/fonts/emoji
```

**Layout width.** A text's width is the furthest any glyph run reaches, never
less than parley's `full_width`. parley under-counts a ZWJ ligature's clusters,
which left emoji families outside the box. Centre and right alignment still use
parley's own width, so a line ending in such a sequence can sit a little off
centre.

Bitmap emoji fonts (Apple Color Emoji's `sbix`, Noto's CBDT) are not drawn. The
native host uses the Noto chunks too.

## 6. Values to text

Floor functions, in `expr.rs`:

| Call | Result |
|---|---|
| `fmt(x)` | A number with up to 12 significant digits; a quantity in its canonical unit with an engineering prefix (`500 g`) |
| `fmt(x, d)` | `d` digits after the point |
| `fmt(q, "kPa")`, `fmt(q, "kPa", d)` | The quantity converted to a unit of the same dimension, with the unit appended; a dimension mismatch is an error |
| `sci(x, d)` | Scientific notation (`1.2e-4`) |
| `str(v)` | Any value as text |

`+` joins strings. A readout is therefore a binding:
`"P = " + fmt(#gauge.slider.value, 2)`.

A runtime signal can drive `text.content` directly. Producers should publish
numbers and quantities onto parameters and let text bind with `fmt`, so a gauge and
its readout read one source. A number or quantity that does reach `text.content`
displays as `fmt` would show it (`text::display`), not as an error.

Graph axes and ticks are not text nodes. A graph node will lay out its labels
internally through `iron_text`.

## 7. Editing

`src/bevy_app/text_tool.rs` and `src-ui/runtime/text_input.ts`.

- **Making text.** T arms the tool; a click makes `auto_width` text and a drag
  makes `fixed` text. The new node is edited at once. Leaving it empty removes it
  with an undo, so no trace stays in history.
- **Starting an edit.** Double-click a selected text node (selects the word under
  the pointer), or press Enter with one text node selected (selects everything).
  Text whose content is bound or driven by a signal is not editable.
- **While editing.** The draft is a preview on `text.content` (`Store::preview`), so
  bindings that read the text, and its bounds, follow every keystroke, and nothing
  enters history.
- **Leaving.** Esc, a press outside the box, or another tool commits one
  transaction. For a new node that commit is folded into its creation (`add text`,
  one undo). The node stays selected.
- **Keystrokes.** The engine sends the draft, the selection (UTF-16 offsets) and the
  caret's window position (`EngineEvent::TextEdit`). The host keeps a hidden
  textarea under the caret holding the same text and sends every change back whole
  (`text_input`). Up and Down go to the engine (`text_motion`), because only the
  canvas layout knows where wrapped lines break.
- **Resizing and rotating.** A selected text node has the box, resize grips and
  rotation of a rect (`select.rs`, `Kind::Text`). A resize also changes the
  sizing mode, as Figma's does: a width-only drag on auto-width text makes it wrap
  (auto height), and any change of height fixes the box. The mode is previewed
  with the size, so the box re-measures during the drag (`Part::text_sizing`).
  Rotation and moving work as for any node.
- **Pasting.** Plain text pasted on the canvas (not inside a field) becomes an
  auto-width text node centred in the view under the pointer, through the
  ordinary paste path (`text::fragment`, "paste text").
- **Feedback.** The caret, selection and box are drawn in their own overlay view
  (`draw_text_overlay`), above the select overlay.

## 8. Inspector

`src-ui/lib/ui/TextSection.svelte`, laid out as in Figma's UI3:

- family: opens `FontPicker.svelte`, with search, a category filter, each family in
  its own face, and a check on the current one;
- weight (limited to the family's axis) and size, with a preset list;
- line height (Auto or %) and letter spacing (%).

  Size, line height and letter spacing are `PropertyField`s, like every other
  inspector number: typed, or Alt-dragged as one previewed gesture that commits
  once. Line height shows "Auto" for 0.

The rest of the section:

- horizontal and vertical alignment;
- a settings popover: resizing, italic, tabular figures.

Below them, Iron's addition: **Content**, typed or bound. The link button takes an
expression (`inspect_bind`); a bound content shows its expression and current
reading, with an unbind button that keeps the current words. The Layout section
hides W and H that the sizing mode computes.

## 9. Not yet

- The inspector shows the node's values while a range is selected, not the
  range's own (Figma shows the range's, or "Mixed").
- Glyph atlas rendering (§5); hinting at small sizes.
- Italic faces in the catalog: only uprights ship; italic is synthesised.
- The full Google Fonts catalogue: needs a server-side manifest and a preview
  sprite per page of the list.
- Prefetching a family while the picker hovers it, and the picker's keyboard
  navigation beyond Enter.
- SVG *import* of `<text>`. Export is done (`iron_svg::export`): `<text>` with
  one `<tspan>` per line and styled part, placed at Iron's layout, plus
  `data-iron-text` for a future exact round trip. A gradient fill and a shadow on
  text export as a solid fill and none, reported as cuts.
- Text in 3D: a 2D view's texture on a plane (`planes.rs` already shows a 2D
  composition in 3D).
- Paragraph spacing, lists, text decoration, OpenType features beyond `tnum`, and
  vertical text.
- A glyph cache for colour glyphs: COLR v1 emoji use clip and blend layers, so a
  view full of large emoji costs more to encode and rasterise than plain text
  (§5).
- The caret does not blink: blinking would re-encode the overlay twice a second.
